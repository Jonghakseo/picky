# Picky UX Writing

사용자가 알아야 할 상태와 다음 행동을 정확히 전달한다. 단순히 짧게 고치거나 내부 용어를 일괄 치환하는 작업이 아니다.

## 먼저 읽기

- [UX Writing Guide](../../../design/UX_WRITING.md): 제품 문체·용어·상태·행동·안전 안내의 정본. 매번 먼저 읽는다.
- [i18n 가이드](../../../docs/i18n.md): 번역 키나 Swift 사용처를 추가·수정할 때 읽는다.
- [저장소 지침](../../../AGENTS.md): 관련 화면 진입점, 검증 범위, 실행 제약을 따른다.

문서 내용을 스킬에 복제하지 않는다. 시각 레이아웃까지 바꾸면 `picky-design-guide`도 사용한다. 사용자·AI가 작성한 본문, 로그, 명령어를 편집하는 요청은 제품 UI 문구 검수와 구분한다.

## 절차

### 1. 범위와 실제 동작 확인

1. `git status --short`로 기존 변경을 확인한다. 검수만 요청받았다면 수정하지 않는다.
2. 화면·상태·사용자 목표를 정하고 해당 View와 backing model/store를 읽는다. 표시 문자열만 보고 행동을 추정하지 않는다.
3. 현재 라벨, 클릭 결과, 전달 대상, 적용 시점, 실패·복원 조건을 대조한다. 전송·삭제·중단은 최종 효과까지 필요한 경로를 추적한다.
4. `Localizable.xcstrings`뿐 아니라 직접 적힌 SwiftUI 문구, AppKit 경고·메뉴, 접근성 라벨, 상태·오류 생성부를 확인한다. 전수 검수라면 화면별 조사 범위와 제외 항목을 남긴다.

### 2. 수정안 검토

- Guide의 용어와 기존 키를 먼저 확인한다. 행동과 상태, 대화와 현재 요청, 카드 선택과 입력 대상 지정을 구분한다.
- 제목·버튼에는 핵심 행동을, 설명에는 필요한 조건을 둔다. 중복 설명은 줄이되 비용·전송 범위·정보 손실·복구 조건은 빼지 않는다.
- 한국어와 영어를 함께 비교한다. 의미·조건·시점·인자 계약을 보존한다.
- 앱 전반 수정은 반영 전에 화면 영역을 나눠 병렬 `challenger` 검토를 받는다. 현재 동작 근거와 양 언어 후보를 주고, 틀린 약속·빠진 예외·새 혼란을 찾게 한다. 사용자가 사전 검증을 명시하면 적용을 멈추고 먼저 완료한다.
- 작은 문구 수정은 직접 대조로 끝낼 수 있다. 결함을 문구로 가리지 않으며, 범위를 벗어나는 행동 수정은 남은 문제로 분리한다.

### 3. 적용과 검증

- 기존 의미가 같은 키를 재사용한다. 다른 행동을 같은 키로 합치지 않는다.
- `Text("key")`와 `L10n.t(...)`의 사용 경계를 지킨다. format 인자의 위치·타입·개수, 단축키, 링크, markdown 강조를 보존한다.
- 저장소 루트에서 `./scripts/check-localizations.sh`를 실행한다. 이 검사는 누락만 확인하므로 자리표시자와 실제 문구의 의미는 별도로 대조한다.
- 상태별 라벨·삭제 가능 조건·회복 동작을 바꿨다면 관련 기존 행동 테스트를 보강한다. 라벨 하나를 바꿨다고 새 테스트 기반이나 전체 제품 테스트를 만들지 않는다.
- 검증은 변경 위험에 맞춘다. 문서만 수정하면 링크·diff, 정적 문구는 번역·format·diff, Swift 연결은 필요한 컴파일, 상태 변경은 production 경로의 결과를 확인한다.
- 실제 화면을 보지 않았다면 잘림·줄바꿈·VoiceOver까지 확인했다고 보고하지 않는다. 앱 재시작, 외부 전송, push는 별도 허가 없이 하지 않는다.

### 4. 보고

검수 결과는 영향이 큰 순서로 `현재 문구 → 문제 → 수정안 → 코드 근거`를 제시한다. 사용자 요청 없이 긴 보고서 파일을 만들지는 않는다.

수정 결과의 기본 표:

| 화면/키 | Before | After | 이유·동작 근거 |
|---|---|---|---|

전체 변경표를 요청받았다면 최종 파일과 기준 revision을 비교해 빠짐없이 작성한다. 한국어·영어와 새 안내, 기존 번역에 연결한 하드코딩 문구도 포함한다. 읽기 전용 검수·적용된 변경·검증되지 않은 범위를 구분한다.

## 완료 조건

- 사용자 목표·상태·다음 행동에 필요한 정보가 남아 있다.
- 액션의 대상·결과·시점과 전송·복원·삭제 예외가 실제 동작과 맞는다.
- 화면·상태·접근성 문구와 두 언어의 의미가 일치한다.
- 번역 키·format 검사를 확인하고, 상태를 바꾼 경우 관련 동작 검증을 실행했다.
- 검증 결과와 제외 범위를 정확히 보고했다.
