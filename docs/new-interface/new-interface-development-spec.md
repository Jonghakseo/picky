# Picky 새 인터페이스 개발명세

## 1. 목적

Picky의 새 인터페이스는 작업을 재개시키는 운영 화면이 아니라, 사용자가 Picky와 무엇을 했는지 돌아보고, 새로운 활용법을 발견하고, 정해진 워크플로우를 시작하게 하는 데스크톱 허브다.

- 대상: macOS에서 Picky를 사용하는 사용자
- 화면 범위: 대시보드, 통계, 가이드 및 업데이트, 빠른 시작, 플러그인, 최근 대화, 설정
- 자유 요청 시작: 기존 Picky 호출창(단축키·음성·텍스트)을 유지한다.
- 메뉴바 Picky 아이콘을 클릭하면 이 창이 열린다. 기존 Companion 패널(상태/플러그인/설정 탭 UI)은 이 창으로 완전히 대체되어 사라진다. 기존 헤더의 마이크 상태 표시는 제거한다.
- 메뉴바 아이콘 우클릭 메뉴에 종료·Dock 숨기기·외형 토글을 유지하고, 새 창 좌측 하단에도 동일 제어를 배치한다.

## 목업 우선 원칙

- `picky-home-mockup.html`은 홈 화면의 정보 구조, 시각 스타일, 목업에 표현된 상호작용의 우선 기준이다.
- 이 문서와 목업이 다르거나 해석이 모호하면 목업을 따른다.
- 이 문서는 목업에 표현되지 않은 데이터, 로딩·빈·오류 상태, 접근성, 기술 제약을 보완한다.
- 구현 중 발견한 차이는 목업을 기준으로 이 문서에도 반영한다.

## 2. 전역 구조

| 메뉴 | 역할 |
| --- | --- |
| 대시보드 | 회고·발견·빠른 시작을 요약하는 홈 |
| 통계 | Pickle 단위의 사용 패턴과 AI 사용량 분석 |
| 가이드 및 업데이트 | 가이드와 제품 업데이트 영상 탐색 |
| 빠른 시작 | 고정 워크플로우 선택과 시작 |
| 플러그인 | 전체 카탈로그 탐색·설치·관리 |
| 최근 대화 | Picky 메인 에이전트와 나눈 가장 최근 대화 이어보기 |
| 설정 | 계정, 권한, 사용 방식, 진단 관리 |

- 사이드바의 모든 메뉴는 독립 페이지로 이동한다. 홈 내부 앵커 이동을 사용하지 않는다.
- 페이지 전환 시 선택 메뉴를 표시하고, 각 페이지의 스크롤 위치는 독립적으로 유지한다.
- Pickle은 Picky와의 일반 대화와 별도의 작업 단위다. 통계는 Pickle을, 최근 대화는 Picky 대화를 다룬다.

## 3. 페이지 요구사항

### 3.1 대시보드

상단 인사말 뒤에 다음 순서로 배치한다.

1. **이번 주 Picky와 한 일**
   - 가장 많이 맡긴 일: 작업 유형, Pickle 수, 비중
   - 가장 깊게 진행한 Pickle: 제목, 후속 지시 수, Picky 위임 수
   - 가장 집중한 프로젝트: 이름, Pickle 수
   - 카드와 `자세히 보기`는 통계 페이지로 이동한다.
   - 첫 사용자 또는 선택 기간에 통계가 없으면 빈 통계 카드로 `아직 이번 주 기록이 없어요`를 표시한다.
2. **가이드 및 업데이트**
   - 가이드와 제품 업데이트를 최신순 단일 피드로 노출한다.
   - 가로 스크롤 카드와 이전·다음 이동을 제공한다.
   - 홈의 카드와 가이드 및 업데이트 페이지의 카드를 선택하면 앱 내부 YouTube 영상 모달을 연다. 모달 동작은 `picky-guides-mockup.html`을 따른다.
3. **빠른 시작**
   - 고정 대표 워크플로우만 제공한다. 초기 구성은 랜딩 페이지 제작, 네이티브 앱 제작, 앱 가이드 시작, 파일 정리 시작이다.
4. **추천 플러그인**
   - 플러그인 이름, 한 줄 설명, 설치 상태를 표시한다.
   - `설치`는 즉시 설치하고 성공하면 `설치됨`으로 바꾼다.
5. **피키 공유하기**
   - 공유 링크 복사, X, LinkedIn 공유를 제공한다.

### 3.2 통계

- 공통 필터: 기간, 프로젝트
- 보기: `작업`, `AI 사용량`

**작업 보기**

- 상단 인사이트: 가장 많이 맡긴 일, 가장 깊게 진행한 Pickle, 가장 집중한 프로젝트
- 작업 분포: 각 Pickle을 다음 유형으로 집계한다.
  - 수정·개선
  - 조사·분석
  - 새로 만들기
  - 검토·문제 해결
  - 미분류 (아직 분류되지 않은 Pickle을 표시해 합계를 항상 맞춘다)
- 분류 방식: 백그라운드 주기 작업이 Pickle 세션들을 훑는다. 결정적 스크립트가 사용자 메시지 N개 샘플링과 도구 호출 빈도 메타데이터를 수집하고, 모델은 그 압축 결과만 보고 빠르게 판정한다(전체 트랜스크립트를 읽지 않는다). 신규·실패·과거 Pickle 소급을 같은 주기 작업이 처리한다.
- Pickle별 작업 기록: 작업명, 프로젝트, 후속 지시 수, Picky 위임 수, 검토 수, 최근 활동 시각
- Pickle 항목은 통계용 읽기 전용 정보다. 상세 화면·모달·필터 변경을 제공하지 않는다.
- 기록이 없으면 `표시할 Pickle이 없어요` 빈 상태를 표시한다.

**AI 사용량 보기**

- 전체·입력·출력/추론·캐시 토큰 요약
- 날짜별 전체 토큰 추이
- 모델·제공업체별 사용량
- 비용은 추정하지 않고, 연결된 제공업체에서 확인하도록 안내한다.

### 3.3 가이드 및 업데이트

- 최신순 단일 피드로 제공한다.
- 카드 선택 시 YouTube 영상을 앱 내부 모달에서 재생한다.
- 모달은 재생만 제공한다. 영상 종료·닫기 후 별도 CTA 없이 원래 피드로 돌아간다.
- 모달은 닫기 버튼, `Esc`, 포커스 복귀를 지원한다.

### 3.4 빠른 시작

- 워크플로우 선택 시 새 Pickle 작업 화면을 만들고, 앱 번들에 포함된 해당 워크플로우의 진행 가이드 문서를 Pickle 첫 지시에 실어 보낸다.
- 가이드는 구현 방법·목적 등 큰 그림을 잡는 질문 주제 5~7개를 명시한다. Pi가 그 가이드를 따라 필요한 정보를 한 질문씩 수집한다. 고정 질문 폼은 두지 않는다.
- 이전 답변에 따라 다음 질문을 Pi가 조정하고, 정보가 충분해지면 작업을 실행한다.
- 사용자가 중간에 나가도 Pickle과 답변은 보존해 다시 이어갈 수 있어야 한다.
- 초기 워크플로우 4종: 랜딩 페이지 제작, 네이티브 앱 제작, 앱 가이드 시작, 파일 정리 시작.

### 3.5 플러그인

- 전체 카탈로그를 카테고리와 검색으로 탐색한다.
- 플러그인 상세는 모달로 표시한다.
- 상세 모달에는 이름, 설명, 사용 사례, 제공자, 버전, 설치 상태와 설치/삭제 행동을 포함한다.
- 홈과 카탈로그 모두 설치는 즉시 실행하고, 성공·실패 상태를 즉시 피드백한다.

### 3.6 최근 대화

- 기존 메뉴바의 '최근 대화'(메인 에이전트와 주고받은 대화)를 그대로 가져온다. 통합 타임라인·대화 구분선은 두지 않는다.
- 가장 최근 대화의 사용자·Picky 메시지를 말풍선 형태로 연속 표시하고, 하단 composer로 그 대화에 이어서 메시지를 보낼 수 있다.
- 구현은 기존 `companionManager.mainAgentMessages` + `CompanionPanelMessagesView`를 재사용한다.
- Pickle 작업 기록, 프로젝트 필터, 검색은 이 페이지 범위에서 제외한다.

### 3.7 설정

한 페이지에 목업의 7그룹을 순서대로 제공한다. 기존 `PickySettingsStore` 항목에 매핑한다.

- 일반: 앱 언어, 화면 모양, 글자/보고서/터미널 크기, 업데이트 채널, 자동 업데이트 확인, 온보딩 다시 보기
- 계정과 에이전트: 제공업체 연결, 메인/Pickle 모델·사고 수준, 읽기 전용 조사 우선, 도구 표시 방식, 경로와 도구 고급 설정
- 음성과 입력: 음성 인식/응답 제공업체, 누르고 말하기·빠른 입력 단축키, STT/TTS 연결 설정
- 화면과 오버레이: 화면 맥락 범위, 스크린샷 품질, 잉크/커서/말풍선 표시, HUD 및 대화 카드 고급 설정
- Pickle과 작업 공간: 준비 후 실행 방식, 기본/메인/고정/최근 작업 폴더, Git 및 워크트리 고급 설정
- 알림·권한·개인정보: 작업 완료/확인/오류 알림, 화면 기록·마이크·음성 인식·접근성·브라우저 권한, 로컬 기록과 데이터 전송
- 고급·진단: 로그 저장 위치, 메인 스레드 위치추적 등 고급 제어

## 4. 데이터와 상태

| 영역 | 필요한 데이터 | 구현 구분 |
| --- | --- | --- |
| 통계 | 사용자 메시지 샘플·도구 호출 메타데이터, 작업 유형, 후속 지시·위임·검토 수, 프로젝트, 활동 시각, 토큰 사용량 | 기존 기록 파생 + 백그라운드 주기 분류 |
| 가이드 | 제목, 발행일, 유형, 썸네일, YouTube URL | 앱 번들 고정 JSON |
| 워크플로우 | 워크플로우별 진행 가이드(스킬/문서), Pickle 연결 | Pi가 가이드 기반 수행 |
| 플러그인 | 카테고리, 검색 인덱스, 설명, 버전, 설치 상태 | 카탈로그 데이터 필요 |
| 최근 대화 | 메인 에이전트 메시지, 재개(이어쓰기) 가능 여부 | 기존 `mainAgentMessages` 재사용 |
| 설정 | 계정, 권한, 사용자 환경설정, 진단 상태 | 기존 설정 연결 |

모든 비동기 영역은 로딩, 빈 상태, 오류, 성공 상태를 가진다. 오류 메시지는 실패 원인과 재시도 행동을 함께 제공한다. 통계·대화·설정 데이터는 기본적으로 Mac 로컬 기록을 기준으로 읽는다.

## 5. 반응형과 접근성

- 기준 레이아웃은 약 1,020px의 macOS 창이다. 창은 리사이즈 가능하며 최소 크기는 760×560이다.
- 메뉴바 아이콘 클릭 시 단일 창을 재사용한다: 없으면 생성, 있으면 앞으로 가져온다(토글 아님). 보던 페이지와 스크롤 위치는 유지한다.
- 카드 영역은 본문 폭 기준 약 640px 이상 3열, 460~640px 2열, 460px 미만 1열로 축소한다(카드 최소 폭 약 280px).
- 사이드바는 190px 라벨 포함 고정이다. 아이콘 모드는 두지 않는다.
- 통계 표·설정 리스트 등 카드가 아닌 영역은 폭에 맞춰 늘어나기만 하면 된다.
- 모바일 웹 레이아웃은 범위에 포함하지 않는다.
- 모든 키보드 조작 요소는 보이는 포커스 상태, 이름, 역할, 상태를 제공한다.
- 가로 캐러셀은 버튼·키보드 화살표·드래그를 지원한다.
- 영상·플러그인 모달은 포커스 트랩, `Esc` 닫기, 닫은 요소로의 포커스 복귀를 지원한다.

## 6. 구현 순서

1. 전역 셸과 독립 페이지 라우팅, 반응형 창 레이아웃
2. 기존 데이터 연결: 최근 대화, 설정, AI 사용량, 기본 플러그인 설치 상태
3. 대시보드와 통계의 Pickle 집계
4. 빠른 시작 워크플로우와 Pickle 생성
5. 가이드/업데이트 영상 모달과 플러그인 카탈로그
6. 빈 상태·오류·접근성·키보드 흐름 검증

## 7. 완료 기준

- 사이드바의 일곱 메뉴가 모두 독립 페이지로 이동한다.
- 대시보드의 통계 요약은 통계 페이지의 같은 기간·프로젝트 데이터와 일치한다.
- 가이드·업데이트 영상은 외부 브라우저 전환 없이 모달에서 재생된다.
- 빠른 시작은 새 Pickle을 만들고 질문을 한 번에 하나씩 진행한다.
- 최근 대화는 Pickle과 혼합하지 않고, 메인 에이전트와의 가장 최근 대화 이어쓰기를 제공한다.
- 좁은 macOS 창에서도 내비게이션과 핵심 행동을 잃지 않는다.
