## 1. 목적과 이번 변경

Picky에게 일을 맡기고, 담당자에게 대화로 방향을 바꾸거나 중단을 지시하고, 결과를 확인한다.
사용자가 도구 운영자가 될 필요는 없다. 전송 방식·작업공간·권한 로그를 매번 해석하게 하지 않는다.

B.04는 선택한 피클의 오른쪽 관리 패널을 추가한다. 컴퓨터 상태와 루틴 목록에서 설정·루틴 편집·
컴퓨터 환경 선택으로 이어진다. 창을 열었다고 실제 작업·연결·권한이 생기지 않는다. 로컬 격리의
구현 후보와 한계는 [컴퓨터 설계](./picky-local-computer-design.md)에 따로 기록한다.

B.03에서 확정한 계약은 유지한다.

| 받은 의견·레퍼런스 | 반영한 동작 |
| --- | --- |
| 팀 카드가 두껍고 정보가 많음 | 한 문장과 작은 전달 칩으로 대체. 역할·지시 원문은 필요할 때 읽음 |
| 에이전트끼리의 대화는 사용자 그룹과 다름 | 전달 칩 → 두 봇의 읽기 전용 대화. 열람은 그룹 가입·새 세션·새 작업을 만들지 않음 |
| Slack 예약 버튼 | 보내기 아이콘과 예약 화살표를 붙인 분할 버튼. 작은 메뉴에서 빠른 예약 또는 직접 시간 설정 |
| 기본 Grok Bot 메신저 | 최근 메시지·시각을 보여주는 목록, 중립 말풍선, 검색 대화상자, 새 대화 진입 |

사용자 이미지의 본문·개인정보·마스코트는 복사하지 않는다. Slack 이미지에서 확인한 것은
분할 버튼과 `나중에 예약` 툴팁이며, 빠른 시간 메뉴 구성은 Picky 제안이다. 계정·결제·마켓플레이스·
플러그인 연결·@ 자동완성은 이번 참조만으로 구현 범위에 추가하지 않는다.

B.02에서 확정한 다음 계약도 유지한다.

| 받은 의견 | 유지할 계약 |
| --- | --- |
| 작업공간과 시안 설명을 빼기 | 모든 화면에서 작업공간명·경로, 컴포저 아래 부연, 목업 설명을 제거 |
| 중단 버튼 없이 채팅으로 제어 | 중단 버튼과 확인 모달 제거. 채팅 지시와 봇의 짧은 응답으로 처리 |
| 도구는 기본 자동 실행, 필요하면 ask | 테스트 승인 양식 제거. 에이전트가 만든 짧은 질문·선택지만 대화에 렌더링 |
| 모든 메시지는 steer, 별도 예약 전송 | steer/follow-up 선택과 작업 뒤 대기열 제거. 보내기 옆 예약 전송 추가 |
| 민트 DM에 모카가 말하면 안 됨 | DM은 사용자와 상대 봇만 발화. 다른 봇의 메시지는 접힌 인계 사건으로 표시 |
| PR 정보 최소화 | 기본 결과는 짧은 문장, branch, PR 번호, 링크. 근거는 상세로 이동 |
| 결과 확인은 Pickle이 처리 | S06을 자동 확인 중 상태로 변경. 사용자 확인·재시도 버튼 없이 모의 조회 후 완료 |
| 중단 UI 불필요 | S07도 채팅으로 중단한 뒤의 짧은 대화만 표시 |

기존 메신저 HTML은 필요한 부분만 수정한다. 새 읽기 전용 대화와 검색은 각각 HTML 파트로
분리한다. 창 전용 시각 변형은 `messenger.css`, 파트의 공통 색과 제어는 `parts.css`를 사용한다.

## 2. 디자인 기준

| 항목 | 기준 |
| --- | --- |
| 첫 시선 | 상대 봇, 대화, 지금 필요한 답 또는 결과 |
| 기본 레이아웃 | 최근 대화 목록과 선택한 대화의 2열. 역할별 섹션을 반복하지 않고 이름·최근 문장·시각을 표시 |
| 제품 화면 | 불필요한 부연·작업공간·운영용 ID·모의 실행 안내를 상시 노출하지 않음 |
| 목업 경계 | 제품 창 바깥에 `오프라인 목업 · 실제 실행 없음`만 유지 |
| 액션과 상태 | Action Blue는 행동·선택, 상태는 문구와 의미색으로 구별 |
| 입력 | 한 가지 보내기. 나중에 보낼 때만 예약 전송을 명시적으로 선택 |
| 세부 근거 | 필요한 경우 상세에서 확인. 적게 보인다는 이유로 데이터까지 삭제하지 않음 |
| 네이티브 한계 | HTML은 macOS 글꼴·입력·재질·접근성의 최종 증거가 아님 |

Light/Dark와 여유 있는 밀도/촘촘한 밀도를 같은 내용으로 비교한다. 본문 14px/13px은 이 목업의
제안값이며 HUD의 canonical 토큰을 바꾸지 않는다. 4px 간격 체계, 중립 표면과 제한된 radius를
사용한다. HTML 아이콘은 실제 SF Symbols 구현이 아니다.

DM에서 반복되는 봇 이름·역할·시각은 각 말풍선 위에 쌓지 않는다. 대화 header와 접근성 이름으로
발화자를 식별한다. 그룹·읽기 전용 에이전트 대화에서는 실제 발화자 이름을 보여준다. 봇의 상태는
header와 필요한 목록 표시로 유지한다. 목록·bubble·composer 크기는 창 전용 variant이며 native HUD를 바꾸지 않는다.

## 3. 정보 구조와 소유권

- Picky는 고정 CBO다. 루나(조사), 민트(구현), 모카(검토)는 기존 Pickle을 재사용한다.
- `예약 날짜 수정`은 사용자가 참여하는 별도 그룹이다. 팀 배정만으로 생성·가입하지 않는다.
  `새 대화 → 그룹 대화 시작`으로 명시적으로 열거나, 검토용 `view=room` 장면을 선택한다.
  그룹을 열었다고 새 Pi 세션이나 workspace를 만들지 않는다.
- 각 Pickle의 고정 홈·하나의 지속 대화·작업공간 분리는 내부 계약으로 유지한다. UI에서 경로를
  감추는 것이 실행 대상을 없애거나 같은 저장소를 무조건 공유하라는 뜻은 아니다.
- DM에는 사용자와 상대 봇의 발화만 표시한다. 그룹에서는 실제 참여자가 직접 말할 수 있다.
- 다른 봇의 전달은 작은 `메시지 보냄/받음 + 상대` 칩으로 표시한다. 내용을 DM 안에 펼치지 않고
  두 에이전트의 읽기 전용 대화로 연다. 별도 UI가 별도 Pi 세션을 뜻하지 않는다.
- 일시적인 하위 실행은 부모 봇의 상세에 속한다. sidebar에 새 연락처를 추가하지 않는다.
- 선택한 대화와 작성 중인 초안은 대화별로 보존한다. 예약 메시지도 작성 시 수신자를 고정한다.

## 4. 공통 화면과 입력

### 4.1 메신저

왼쪽 목록은 최근 문장과 시각으로 구분한다. 검색 버튼 또는 ⌘K로 검색 창을 열어 전체·Pickle·메시지·
그룹을 찾는다. 현재 열린 대화의 본문과 다른 대화의 최근 미리보기를 검색한다. 제품의 전체 이력·
권한 검색 구현이 아니다. 선택은 해당 대화로 이동하고 초안을 유지한다. header에는 상대·상태,
요청 근거를 보는 `상세`와 피클 관리 아이콘을 둔다. 중단 버튼은 없다.

composer는 입력에 맞춰 높이가 늘어나는 한 줄 입력창과 전송 분할 버튼이다. 하단 설명, 작업공간, 전송 mode,
예시 문장 채우기 버튼은 없다. 입력창 placeholder는 수신자만 알려준다.

- Enter는 항상 일반 메시지 전송이다. 실행 중이면 steer, idle이면 같은 지속 대화의 다음 turn이다.
- Option+Enter에도 follow-up 의미를 부여하지 않는다. Shift+Enter는 줄바꿈이다.
- IME 조합 중 Enter는 전송하지 않는다. 실제 NSTextView/한글 입력기는 별도 검증해야 한다.
- 질문의 선택 버튼은 일반 메시지와 다르다. 원 질문의 응답 ID로 처리한다.
- 중단은 `이 작업 중단해줘`, `그만해`, `멈춰줘` 같은 채팅 지시로 한다.

실제 제품에서는 Pi가 중단 의도·대상을 판단하고 내부 abort와 하위 실행 정리를 요청한다.
HTML은 몇 가지 정해진 문장만 분기하는 모의 동작이다. 이 키워드 분기를 Swift나 agentd의
의도 해석기로 가져오지 않는다. 장기 도구 실행 중 지시 수신과 중단 지연은 B §13.4의 별도 실험이다.

### 4.2 리뷰 도구

밝기·밀도·장면 선택·처음부터·피드백은 제품 창 바깥에 둔다. 장면 이동은 검토용 fixture를
새로 구성하며 대화 초안과 모의 예약을 초기화한다. 피드백과 저장한 피클 설정·루틴·컴퓨터 선택은 보존한다.

`#screen=S04&view=mint&theme=dark&density=compact&panel=files`처럼 화면·대화·시각 변형을
지정할 수 있다. hash는 완전한 대화 저장 파일이 아니다. 새로고침하면 선택 장면의 기본 fixture로
돌아가므로 사용자가 입력한 대화·질문 응답·예약의 제품 영속성을 증명하지 않는다.

## 5. 화면별 UX

| 화면 | 첫 화면과 사용자 목표 | 사용자 행동 | 다음 상태 |
| --- | --- | --- | --- |
| S01 의뢰 | Picky와 짧은 인사, 작성할 메시지 | 의뢰 보내기 또는 예약 전송 | S02 팀 배정 또는 예약 보관 |
| S02 팀 배정 | 짧은 답과 작은 전달 칩 | 두 봇의 대화 읽기 또는 담당자 DM 열기 | 열람은 S02 유지, 담당자 DM은 모의 S03 |
| S03 실행 중 | 담당자의 짧은 진행 메시지 | 수정 지시, 대화로 중단, 메시지 예약 | S04 질문, S07 중단 또는 예정 시각까지 보관 |
| S04 선택 질문 | 에이전트가 만든 질문과 선택지 | PR로 공유 / 수정안만 남기기 | S05 결과 |
| S05 결과 | 짧은 완료 문장과 최소 PR 카드 | PR 링크, 접힌 인계, 필요한 상세 | 기존 대화를 유지하며 근거 열람 |
| S06 자동 확인 | 담당자가 결과를 확인 중이라는 짧은 메시지 | 별도 확인 작업을 요구하지 않음 | 모의 종료 기록 조회 후 S05 |
| S07 대화로 중단 | 사용자의 중단 지시와 봇의 짧은 답 | 새 메시지로 다음 의뢰 가능 | 같은 지속 대화에서 S03 |

### S01 · 의뢰

초기 composer에는 다음 문장을 넣어 흐름을 시작할 수 있게 한다. 시안 설명 문장은 별도로 넣지 않는다.

> 예약 화면에서 날짜를 바꾸면 인원이 초기화돼. 원인을 조사하고 수정한 뒤 별도로 검토해줘. 배포는 하지 마.

사용자가 편집한 입력은 그대로 표시한다. 봇 답변은 정해진 시나리오이며 임의 의뢰를 실제로
이해하지 않는다. 모델·계정 연결과 파일 작업 허용이 준비된 상황을 가정한다.

### S02 · 팀 배정

Picky는 `담당자들에게 전달했어요`라고 답한다. 아래에 루나·민트·모카로 보낸 작은 전달 표시만 둔다.
두꺼운 팀 카드, 역할 목록, 그룹 진입 CTA는 없다. 칩을 클릭하면 Picky ↔ 해당 Pickle의 지시와
응답을 읽는다. 열고 닫아도 원 DM·초안·요청 상태가 바뀌지 않는다. 담당자 DM 선택은 검토용 진행
fixture로 이동하지만 읽기 전용 인계 열람은 진행 장면을 바꾸지 않는다.

### S03 · 실행 중

민트 DM에서는 민트만 답하고 루나의 전달은 `메시지 받음 · 루나`라는 작은 표시로 보인다.
같은 규칙을 배정·조사·검토·최종 보고에 적용한다. 사용자가 명시적으로 연 그룹에서는 실제 참여자가 발화한다.

일반 입력은 모두 현재 작업에 전달한다. 예약하지 않은 입력을 다음 작업 대기열로 밀지 않는다.
이 목업에서 첫 수정 지시 뒤 S04 질문으로 이동하는 것은 고정된 시나리오다. 실제 제품이 모든
수정 지시마다 질문해야 한다는 뜻이 아니다.

### S04 · 에이전트의 선택 질문

도구와 테스트는 기본 자동 실행한다. 명령·cwd·branch·위험 설명을 한꺼번에 쌓은 승인 양식은 없다.
이 장면은 이미 수정·검토한 내용을 PR로 공유할지 사용자의 선택이 필요한 상황이다.

> 수정과 테스트를 마쳤어요. PR로 공유할까요?

선택지는 `PR로 공유`, `수정안만 남기기`다. 두 번째 선택도 테스트를 거절하거나 실패했다는 뜻이
아니다. PR 생성 여부만 달라진다. 일반 채팅을 버튼 선택으로 자동 해석하지 않는다.

실제 제품의 기본 자동 실행은 권한 검사 제거가 아니다. 계정 권한·TCC·사용자 금지·자원 소유권을
유지하고, 추가 판단이 필요하면 에이전트가 ask를 호출한다. 필요한 정보를 짧게 보여주되 실제
질문·응답·행동의 귀속을 잃어서는 안 된다.

### S05 · 결과

기본 PR 카드는 `#128`, `fix/date-change`, `PR 보기` 링크만 보여준다. 테스트 개수, 파일 개수,
실행 command, 관찰 revision, workspace는 기본 대화에 나열하지 않는다. 자세한 근거는 상세에서 본다.

PR 링크는 [별도 로컬 PR 파트](./prototypes/picky-b-messenger/pull-request.html)를 연다. 실제
GitHub에 PR을 만들거나 존재하지 않는 GitHub URL을 실제 결과처럼 제공하지 않는다. 별도 화면에도
제품 화면 바깥의 목업 표시를 둔다.

민트 DM에서 모카의 검토는 작은 수신 표시다. 클릭해야 모카 ↔ 민트의 대화가 열린다.
모카를 민트 DM의 참여자처럼 렌더링하지 않는다.
Picky DM은 Picky가 결과를 전달한다. 현재 선택한 대화를 강제로 다른 DM으로 바꾸지 않는다.

### S06 · 자동 확인

사용자에게 ‘확인 필요’를 해결하라는 카드나 재시도 버튼을 주지 않는다. 담당자가 읽기 전용으로
저장된 종료 기록을 대조한다. 목업에서는 5초 뒤 확인된 종료 기록이 있는 장면으로 전환한다.
중단·다른 장면 이동 이후 오래된 모의 확인이 결과를 덮어쓰지 않아야 한다.

이는 실제 복구 구현이 아니다. 제품에서는 모르는 결과를 성공으로 바꾸거나 외부 효과를 확인 없이
다시 실행하면 안 된다. 스스로 해결하지 못하고 사용자의 답이 필요할 때만 ask로 묻는다.

### S07 · 대화로 중단

중단 지시와 `진행 중인 작업을 중단했어요`라는 짧은 답만 보여준다. 중단 버튼·중단 확인 모달은 없다.
이미 완료한 파일 변경·외부 효과를 되돌렸다는 뜻은 아니다. 작업 시작 전 중단했다면 가짜 diff도 없다.

중단은 해당 작업과 하위 실행에 적용한다. 독립적인 예약 메시지는 자동 삭제하지 않는다. 예약 삭제는
예약 목록에서 별도로 수행한다. 중단 뒤 새 의뢰도 같은 봇·같은 지속 대화에서 이어진다.

## 6. 예약 전송 파트

보내기와 예약 화살표를 붙인 분할 버튼을 쓴다. 화살표에 `나중에 예약` 툴팁과 접근성 이름을 둔다.
누르면 전송 버튼 바로 위의 작은 메뉴에 `30분 후`, `내일 오전 9시`, `직접 시간 설정…`이 나온다.
직접 설정과 기존 예약 변경만 [별도 시간 설정 HTML](./prototypes/picky-b-messenger/schedule-message.html)을 연다.
메시지와 수신자는 메뉴를 열 때 고정한다. iframe에서 임의 수신자나 본문을 지정하지 않는다.

- n분 뒤: 직접 분 입력을 제공한다. 빠른 예약은 추가 양식 없이 바로 보관한다.
- 특정 시점: 날짜·시각과 시간대를 표시한다. 과거 또는 잘못된 시간을 거부한다.
- 예약 중에는 Pi에 전달하지 않는다. 예약 목록에서 시각 변경·삭제가 가능하다.
- 실제 시각에 도달하면 저장된 수신자에게 한 번 전달한다. 현재 보고 있는 DM으로 바뀌지 않는다.
- 전달 의미는 일반 메시지와 같은 steer다. ‘현재 작업이 끝나면’이라는 follow-up 조건이 아니다.
- 예약 편집 중 원 예약이 이미 발송되거나 삭제되었다면 새 예약으로 부활시키지 않는다.
- child 메시지는 해당 iframe, 현재 편집 token, 원 상태를 확인한다. 지난 dialog나 다른 frame의 입력을 무시한다.
- 다시 열 때 이전 폼을 먼저 숨기고, 새 수신자·본문·편집 token의 초기화 응답을 받은 뒤 표시한다. 이전 예약의 폼이 새 요청으로 제출되지 않게 한다.

목업은 탭이 열려 있을 때 브라우저 시간으로 동작하며 앱 영속 저장소나 OS 스케줄러를 쓰지 않는다.
새로고침·장면 초기화·탭 닫기 뒤 예약은 유지되지 않는다. 실제 제품의 영속성·재시작·DST·missed-run은
B §9.2.1의 구현·검증 대상이며 이 목업으로 입증하지 않는다.

## 7. 읽기 전용 대화·검색·상세

### 7.1 에이전트 간 대화

[대화 파트](./prototypes/picky-b-messenger/agent-conversation.html)는 `Picky ↔ 루나`처럼 두 참여자를
header에 표시한다. 본문은 실제 발신자를 붙인 중립 말풍선이고, 아래에는 보기 전용 표시와 닫기만 둔다.
입력창·전송·그룹 가입·새 봇 생성은 없다. 이 목업에서는 선택한 인계의 짧은 fixture만 전달한다.
제품의 전체 두 봇 이력이나 권한 검사를 구현한 것이 아니다.

부모는 자신의 원 상태·대화와 초기화 token을 고정한다. frame 출처와 token을 확인하고, 새 내용을
그렸다는 응답 뒤에만 표시한다. 닫기는 원래 전달 칩으로 돌아온다. 대화 열람은 작업을 중단·재시도하거나
새 최상위 turn을 만들지 않는다. 텍스트는 HTML로 실행하지 않는다.

### 7.2 검색과 새 대화

[검색 파트](./prototypes/picky-b-messenger/chat-picker.html)를 검색과 기존 상대 선택에 재사용한다.
사용자가 새 대화를 선택해도 기존 Pickle의 지속 대화를 연다. `그룹 대화 시작`만 사용자 그룹을 추가한다.
검색어·종류 필터, 방향키·Enter·⌘1~9·Escape를 제공한다. 미일치는 빈 결과로 표시한다.
항목은 부모가 제공한 현재 fixture의 허용 ID로만 선택하며 임의 도구·URL·권한 변경을 실행하지 않는다.

### 7.3 상세와 키보드

상세는 진행·변경 파일·검증 기록을 읽기 전용으로 연다. 상세를 본다고 작업이 멈추지 않는다.
원 요청·관찰 정보는 내부에 유지하고 사용자가 필요한 근거를 선택해서 본다.

모든 활성 버튼에 이름과 키보드 경로를 둔다. 상세 탭은 좌우 화살표, dialog는 Escape로 닫고
원래 제어로 focus를 돌려준다. native VoiceOver·TCC·PTT·NSTextView의 동작은 별도 제품 검증 대상이다.
일반 버튼은 arrow cursor와 hover를 사용한다. Reduce Motion에서 의미가 유지되도록 장식적 motion은 없다.

### 7.4 피클별 우측 관리 패널

관리 아이콘은 현재 DM 상대의 [컴퓨터·루틴 목록](./prototypes/picky-b-messenger/bot-overview.html)을
연다. 설정 톱니, 컴퓨터 환경, 루틴 추가·편집으로 이어진다. 사용자 그룹은 봇이 아니므로 이 아이콘을
보이지 않는다. 기존 요청 상세와 같은 오른쪽 자리를 사용하고 동시에 열지 않는다.

넓은 창에서는 대화 옆에 440px 패널을 둔다. 1100px 이하에서는 선택한 대화 자리를 관리 화면으로
전환해 양쪽을 억지로 좁히지 않는다. 닫으면 원 대화·초안으로 돌아간다. 목록에서 다른 피클을 선택하면
그 피클의 관리 홈으로 이동한다. 열람·설정 변경은 새로운 봇·그룹·Pi 세션·turn을 만들거나 작업을 멈추지 않는다.

| 화면 | 사용자 행동 | 저장·반영 범위 |
| --- | --- | --- |
| 설정 | 이름·레이블·설명·알림 편집 후 `설정 저장` | 선택한 피클의 표시 설정. 이름 변경은 같은 Bot ID·홈·세션을 유지 |
| 루틴 | 추가·이름·지침·활성 상태·여러 실행 시기를 편집하고 저장 | 해당 피클 소유 정의만 변경. 다른 피클의 루틴이나 내장 Cron 엔진을 끄지 않음 |
| 실행 시기 | 매일·매주 시각과 시간대, 또는 GitHub PR 병합 이벤트 | 일정과 이벤트를 구분. 이벤트는 계정·source 권한 준비 전 `연결 필요` |
| 테스트 실행 | 저장한 정의의 흐름 확인 | 이 HTML에서는 `모의 실행 기록`만 추가. 실제 도구 호출·Pi 수락·성공을 만들지 않음 |
| 루틴 삭제 | 해당 편집 화면에서 삭제 확인 | 목업 정의와 모의 기록 제거. 실제 제품의 trigger 중지·대기 정리·감사 기록 보존은 B §9의 별도 계약 |
| 컴퓨터 환경 | 로컬 Linux 컴퓨터·분리된 브라우저·내 Mac 중 선택 저장 | 해당 피클의 환경 선호만 저장. 설치·연결·로그인·TCC·파일 허용은 하지 않음 |

설정의 이름은 표시 이름이다. Picky의 고정 CBO 정체성이나 내장 시스템 프롬프트를 편집하는 필드가 아니다.
알림을 꺼도 대화의 ask와 실행 상태를 숨기지 않는다. 실제 OS 알림 허용을 구현한 것도 아니다.

루틴은 목업에서 피클당 12개, 실행 시기 4개, 모의 기록 20개까지 둔다. 제품의 자원 한도로 확정한
숫자가 아니다. 테스트는 저장된 정의에 귀속되며, 미저장 변경이 있으면 먼저 저장하거나 취소하게 한다.
예약 메시지와 Routine 정의는 서로 다른 데이터다. 채팅 중단·루틴 삭제가 독립적인 예약 메시지를 삭제하지 않는다.

컴퓨터는 실제 화면 대신 미연결 상태를 보여준다. 환경 선택을 저장해도 `설정 필요`이며, 내 Mac은
사용자의 물리 화면과 권한을 공유하는 비격리 실행임을 알린다. Linux는 Mac 앱을 실행하는 환경이 아니고,
브라우저 프로필 분리는 OS·파일 권한 격리가 아니다. 모델 인증·Pi 기억·사용자 홈을 자동 공유하지 않는다.

`bot-management.js`가 목업의 부모 상태와 localStorage를 소유하고, 네 HTML 파트는 화면과 폼을 담당한다.
파트를 단독으로 열면 예시 화면이다. 저장·이동은 메신저 안에서 열린 파트로 검토한다.
저장 key는 `picky.mockup.b04.bot-management`이며 외부 전송은 없다. 저장된 값은 다시 읽어 화면에 반영하고,
저장 실패는 이 탭의 메모리에만 남았음을 알린다. 잘못된 저장 데이터가 봇·권한·실행 동작을 추가할 수 없다.

저장 전 입력은 피클·화면·루틴별 메모리 초안으로 유지한다. 뒤로 가기·닫기·피클 전환으로 버리지 않고,
`변경 취소`로 명시적으로 버린다. 새로고침하면 미저장 폼 초안은 사라진다. 저장된 설정·루틴은 남지만,
이는 제품 저장소·OS 스케줄러의 영속성 검증이 아니다.

부모는 현재 Bot ID·편집 루틴 ID·초기화 token·원 상태를 고정한다. child가 다른 소유자나 URL·도구를
지정할 수 없으며, 늦게 도착한 이전 화면의 저장·삭제·테스트를 거부한다. 현재 폼의 초기화 응답 뒤에만
보여주고 이름·설명·지침은 HTML이 아닌 문자로 렌더링한다. Escape는 관리 패널을 닫고 원 아이콘에 focus를 돌린다.

## 8. 피드백

제품 창 바깥의 `이 화면 피드백`에서 화면 ID·대화·상태·밝기·밀도·상세·관리 하위 화면과 의견을 기록한다.
브라우저 localStorage만 사용하고 자동 전송하지 않는다. 저장 불가 시 메모리에 보관하고 내려받기를
안내한다. 작성 중 다른 장면으로 이동해도 의견의 원 화면 귀속은 유지한다.

이전 B.01~B.03 의견은 같은 브라우저에 남아 있으면 보존한다. 새 내려받기 파일명은 `picky-b04-feedback.md`다.
공유하려면 내려받은 Markdown을 대화에 전달한다. 사용자가 제공한 원본 피드백 파일은 수정하지 않는다.

## 9. 확인할 사용자 계약

- 의뢰 → 작은 전달 표시 → 담당자 DM → 수정 → ask → 결과가 이어진다.
- 전달 칩을 열어도 사용자 그룹이 생기거나 초안·실행 상태가 바뀌지 않는다. 두 실제 발화자가 보이고 입력창은 없다.
- 사용자 그룹은 새 대화에서 따로 시작한다. 검색·대화 선택이 기존 초안을 보존한다.
- 작업공간·컴포저 부연·전송 mode·중단 버튼이 모든 장면에서 제거돼 있다.
- 일반 Enter와 Option+Enter는 steer이며, Shift+Enter·IME 조합은 전송하지 않는다.
- 중단은 채팅으로 처리하고, 부정 문장 `중단하지 마`를 중단 명령으로 처리하지 않는다.
- 테스트 결과는 도구 승인 없이 생기고, ask의 선택은 PR 생성 여부만 바꾼다.
- 민트 DM에는 모카·Picky의 발화가 없고, 인계 원문은 읽기 전용 대화에서만 본다.
- PR 카드가 최소 정보만 보이며 별도 로컬 페이지로 연결된다.
- 작은 예약 메뉴와 직접 시간 설정 모두 조기·중복 전달하지 않고 원 대화로 보낸다. 변경·삭제·Escape가 가능하다.
- 자동 확인은 중단·장면 전환 후 오래된 결과를 적용하지 않는다.
- 피클 설정·루틴·컴퓨터 선택이 저장·재열기·새로고침 후 원 소유자에게만 반영된다. 미저장 초안도 다른 피클로 섞이지 않는다.
- 루틴 테스트는 저장된 정의의 모의 기록이며, 삭제·이전 iframe의 늦은 이벤트로 되살아나지 않는다.
- 관리 화면 열람·환경 선택은 대화·작업·예약·실제 Computer 권한을 바꾸지 않는다.
- 피드백 저장·복원·내려받기와 light/dark·밀도·좁은 화면이 동작한다.

## 10. 검증 방법과 한계

[브라우저 검증 스크립트](./prototypes/picky-b-messenger/verify-browser.js)는 실제 HTML과 예약 iframe을
별도 임시 프로필의 headless Chrome에서 조작한다. 기존 `playwright-cli`에 포함된 `playwright-core`와
설치된 Chrome을 재사용하며 새 의존성이나 실행 중인 사용자 profile을 요구하지 않는다.

```bash
node docs/prototypes/picky-b-messenger/verify-browser.js
```

이전 B.02는 2026-09-13 `file://` 검증에서 메신저와 두 HTML 파트의 10개 검증 묶음을 통과했다.
브라우저 오류와 외부 요청은 0건이었다. Light/Dark·좁은 화면·예약 창 스크린샷과 내려받은 피드백도 확인했다.
재오픈한 예약 폼이 이전 token으로 제출되는 오류를 재현한 뒤 초기화 완료 응답으로 고쳤다.

B.03은 메신저와 4개 HTML 파트를 실제 `file://`로 열어 14개 검증 묶음을 통과했다.
전달 쌍·읽기 전용·사용자 그룹 분리·초안 보존·빠른 예약·검색을 확인했다. 본문 검색은 sidebar의
최근 문장이 바뀌어도 현재 대화의 앞선 문장을 찾는다. Light/Dark·1024px/390px 화면과 Escape 후
원 전달 칩으로 돌아오는 focus도 확인했다. 브라우저 오류·외부 요청은 0건이며, 내려받은 피드백도 읽었다.

B.04는 메신저와 8개 HTML 파트를 실제 `file://`로 열어 **20개 검증 묶음**을 통과했다.
브라우저 오류·외부 요청은 0건이다. 피클 전환과 저장·새로고침 후 설정 귀속, 미저장 폼 초안,
이름의 문자 렌더링, 이전 iframe의 늦은 저장·삭제 거부를 확인했다. 빈 시각을 임의의 09:00으로
바꾸지 않는 것, 복수 시기·이벤트 연결 필요·일시중지·모의 기록·삭제도 확인했다. 컴퓨터 선택을
저장해도 `설정 필요`이고 다른 피클에 섞이지 않는다.

1440px 라이트와 1024px·390px 다크에서 관리·설정·루틴 화면을 캡처해 읽었다. 컴퓨터 선택과
기존 메신저 파트, 내려받은 피드백 원문도 확인했다. 루틴의 긴 폼은 내부 스크롤로 저장 버튼에
접근하며 Escape는 원 관리 아이콘으로 돌아간다. 검증 중 발견한 삭제 버튼 줄바꿈·입력 스타일·
제목 포커스 표시를 고친 뒤 같은 20개 검증을 다시 통과했다.

이 검증은 모의 화면과 메시지 전달만 증명한다. 실제 Pi 실행·기본 자동 도구 권한·ask enforcement·
장기 도구 중 채팅 중단·예약 영속화·GitHub PR·OS 복구·macOS 접근성을 검증한 것이 아니다.
공식 브라우저/네이티브 UI 검증과 기능 구현은 따로 수행해야 한다.
